# Workflow Outputs

This document describes the standardized output structure generated by the **3D Mechanobiological Analysis Suite**. 

To ensure reproducibility, each analysis run generates a dedicated output folder. This folder preserves the physical voxel calibration, parameter logs, visual quality-control (QC) figures, and quantitative tables.

---

## 1. Continuous ECM Density Mapping

When running the continuous density workflow, the software creates a root folder (e.g., `Module_Continuous_Density`) containing the following subdirectories:

*   **`01_Raw_vs_Colormap/`**
    *   Contains `.png` or `.jpg` image files showing a side-by-side comparison of the raw Z-projected collagen signal and the resulting normalized, threshold-free continuous colormap.
*   **`04_Overlay/`**
    *   Contains visual overlays of the continuous density colormap on top of the original ECM structure. Useful for visual validation of densification centres.
*   **`05_Z_Profile_Summary/`**
    *   Contains plots demonstrating the mean and maximum signal depth-dependence (Z-profile) after background correction. This confirms signal continuity and attenuation across the 3D acquisition volume.
*   **`08_Tables/`**
    *   Contains `CSV` and `XLSX` files with the quantitative descriptors for each analyzed position.
    *   **Key metrics exported:** `Gini Density Coefficient`, `Densification Index` (top 10% vs remaining 90% signal ratio), `Remodelling Contrast Index`, and `Max Signal (AU)`.

---

## 2. SAM2-assisted Degradation and Tunnel Annotation

When running the SAM2-assisted annotation workflow, the software creates a root folder containing plane-by-plane annotations and 3D object reconstructions:

*   **`Raw_Planes/`**
    *   Uncompressed images of every reviewed Z-plane in the confocal stack.
*   **`Binary_Masks/`**
    *   The accepted binary masks for degradation/tunnel-like regions generated via SAM2 prompts.
*   **`Cell_Masks/`**
    *   Binary masks corresponding to the cellular context (if a cell channel was provided).
*   **`Semantic_Labels/`**
    *   Machine-learning-ready multiclass images. Classes are strictly encoded as: `0 = Background`, `1 = Cell`, `2 = Degradation/Tunnel`. These image-mask pairs are explicitly formatted for future U-Net or nnU-Net supervised training.
*   **`3D_Reconstructions/`**
    *   Contains MATLAB `.fig` and `.png` files rendering the connected 3D degradation/tunnel objects in physical space ($\mu m$).
*   **`Metrics/`**
    *   Contains `CSV` and `XLSX` files summarizing both plane-level and 3D object-level metrics.
    *   **Key metrics exported:** Plane review outcome (Positive/Negative), 2D Degradation Area, 3D Degradation/Tunnel Volume ($\mu m^3$), Object Count, Z-extension ($\mu m$), and Degradation-to-cell area ratio.

---

## Output Data Management

*   **Physical Calibration:** All spatial metrics (Lengths, Areas, Volumes) are automatically converted to physical units ($\mu m$, $\mu m^2$, $\mu m^3$) using the metadata extracted via Bio-Formats. 
*   **External Storage:** Because multidimensional `.lif` files and the resulting datasets can be extremely large, you should configure your global output directory to a local hard drive or institutional server. Do not store massive output folders directly inside the GitHub repository to avoid bloat.

## 3. Public repository contents and local run outputs

The public repository contains the software implementation, documentation, metadata files and compact representative figures used to illustrate expected outputs. Full analysis outputs are generated locally by the user and should be stored with the corresponding project data.

Recommended repository-visible material:

- source code;
- README and documentation;
- compact PNG/JPG figures for documentation;
- example folder structure;
- citation and software metadata files.

Recommended local or institutional storage material:

- raw microscopy acquisitions;
- complete run-output folders;
- MATLAB workspaces and large arrays;
- SAM2 model weights;
- exported TIFF stacks;
- project-specific laboratory records.
